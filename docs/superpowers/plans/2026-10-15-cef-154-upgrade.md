# CEF 154 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move bevy_cef from CEF `152.3.0+152.0.6` to `154.5.0+154.0.34` for the 0.14.0 release. CEF 154 removed `register_extension`, so `window.cef` and `CefExtensions` are re-implemented on top of `on_context_created` without changing any public API.

**Architecture:** The work lands on `feat/cef-154` in three commits. Task 1 replaces the V8-extension mechanism while the workspace is **still on CEF 152**: it compiles there (`v8_value_create_function` and `V8Context::eval` exist in both versions) and is verified against the installed 152 runtime, so any later runtime regression can be pinned on CEF 154 alone. Task 2 updates the user-facing docs for the new mechanism. Task 3 bumps the dependency, reinstalls the local CEF runtime and repeats the runtime checks on 154. Task 4 runs pre-release checks and drafts the PR text without pushing.

**Tech Stack:** Rust 1.97.1+ (edition 2024), Bevy 0.20, cef-rs `cef` / `cef-dll-sys` (152.3.0+152.0.6 → 154.5.0+154.0.34, Chromium 154.0.8037.98), CEF render-process V8 API.

**Spec:** `docs/superpowers/specs/2026-10-15-cef-154-upgrade-design.md`

## Global Constraints

- Target pin: `cef = { version = "=154.5.0+154.0.34" }` and `cef-dll-sys = { version = "=154.5.0+154.0.34", features = ["sandbox"] }`; `export-cef-dir@154.5.0+154.0.34`.
- `Cargo.lock` is changed only with `cargo update -p cef -p cef-dll-sys --precise 154.5.0+154.0.34`. Never run a bare `cargo update`.
- Public contracts stay unchanged: the JavaScript API `window.cef.brp` / `window.cef.emit` / `window.cef.listen`, the Rust API `CefExtensions::new().add(name, code)` and `CefPlugin::extensions`. The browser process keeps passing extensions as JSON in the `bevy-cef-extensions` switch, and `CefExtensions` keeps its `HashMap` field.
- Extension script URL: `cef://localhost/__extensions__/{name}.js`.
- Injection order in every V8 context: `window.cef` → extensions (name order) → `PreloadScripts`.
- Release version `0.14.0`; CHANGELOG edits go under the existing `## v0.14.0` heading.
- Project Rust rules apply (`~/.claude/rules/rust.md`). The only line comments allowed are `// TODO:`, `// NOTE:` and `// SAFETY:`, and no comment cites a spec or plan. Every `#[test]` has a two-part doc (the asserted contract, then `Case:`). Imports form one block at the top of the file (test modules are the exception), and paths are not written inline. All comments are in English.
- Static checks stay clean. CI runs these commands: `cargo clippy --workspace --all-targets --all-features -- -Dwarnings`, `cargo fmt --all -- --check`, `cargo test --workspace --no-default-features --tests`, `cargo test --doc`.
- **Ask the user before any command that writes to `$HOME/.local/share/cef`.** That covers `export-cef-dir --force`, `make install-debug-render-process` and `make setup-*`.
- Stage files by explicit path; never run `git add -A` or `git add .`. The untracked `.commandcode/` and `examples/sprite_regression.rs` belong to the user. The throwaway probe `examples/zz_cef154_probe.rs` is never committed.
- Do not push or open a PR unless the user asks.
- Scratch output (logs, scripts, PR draft) goes to `target/cef154-checks/`. It is git-ignored and survives across sessions.
- Only one CEF app runs at a time. Every example uses CEF's default cache directory, and a second instance fails `cef_initialize` and panics. The probe run, `smoke.sh` and each interactive example run one after another, never overlapping, and the user closes each example before the next one starts.
- Example logs are captured with `NO_COLOR=1` (through `run_for.sh`). Otherwise Bevy's log formatter wraps `ERROR` in ANSI escapes, and greps for it miss.
- Out of scope unless the user adds it: a null check on `api_hash()` with a "rerun make setup-*" message. Task 3 Step 8 collects the evidence for that decision.

## Deviations from the spec (decided while planning)

1. **One pure unit test is added** (`extension_script_url_names_the_extension`), although spec §4 says no new unit tests. It needs no V8 context and pins the URL the docs promise.
2. **The `extensions` example and the `CefExtensions` rustdoc example are fixed to call `window.cef.emit({ score: score })`.** `CefApiHandler::execute_emit` serializes only its first argument, so the current `window.cef.emit('score_update', { score: score })` sends the string `"score_update"`. `ScoreUpdate` then fails to deserialize, and nothing reaches the log on any CEF version. Spec §4 expects `myGame.sendScore()` to reach the Bevy log, which needs this fix.
3. **`preload_scripts` and `js_emit` are added to the runtime smoke list.** The spec's list leaves out `preload_scripts`.
4. **The transparency check is observed through bevy_cef's alpha hit-test:** a click on a transparent pixel must not reach the page, and a click on an opaque pixel must. On macOS, sprite picking still blocks lower entities across the whole rect (a documented limitation), so whether a click reaches what is behind the webview depends on Bevy picking, not on CEF 154. The CEF 154 risk (an opaque OSR root layer) shows up as alpha 255 in those pixels. For this reason, the spec's literal check (a click on a transparent pixel reaches the entity behind the webview) is waived.
5. **`bind_cef_api` also logs a failure when setting `cef` on the global object fails.** The spec's error table does not list this case. The added log follows the table's pattern.

## Review Focus

1. **Upgrading users who keep the old CEF runtime.** A user bumps bevy_cef but skips `make setup-*`, so the CEF 152 framework (and a 152 render process) stays installed. They expect a failure they can recognize. → Task 3 Step 8 runs a 154-bound example against the still-installed 152 runtime and records the symptom for the CHANGELOG/PR text and the deferred `api_hash` decision.
2. **Reloads and navigations.** Every new document gets a new V8 context. `window.cef`, the extensions and the preload scripts must run again, and `listen`/`brp` must keep working. → The probe's reload check in Task 1 Step 11 and Task 3 Step 12.
3. **Extension names that are not URL-safe.** A name with a space, slash or non-ASCII characters must still run; its console source may be percent-encoded. → The probe's `a broken` extension (with a space) in Task 1 Step 11 and Task 3 Step 10.
4. **Cross-site (out-of-process) iframes.** They run in another render process, which must also get `window.cef` and the extensions. → The probe's `https://example.com/` iframe in Task 1 Step 11 and Task 3 Step 10 (needs network). This check is informational only: Blink creates a frame's V8 context only when the frame runs script, so the result depends on example.com still loading one.
5. **An empty or failing extension next to valid ones.** An empty extension is skipped, a failing one is reported, and the extensions after it still run. → The probe's `a broken` / `b_probe` / `c_empty` extensions in Task 1 Step 11 and Task 3 Step 10.

```rust
/// Defines `window.cef` in `context` with the `brp`, `emit` and `listen` functions.
///
/// On failure, logs with `cef_error!` and leaves `window.cef` undefined.
fn bind_cef_api(context: &V8Context) {
    let Some(global) = context.global() else {
        cef_error!("failed to bind window.cef: the context has no global object");
        return;
    };
    let Some(mut cef) = v8_value_create_object(None, None) else {
        cef_error!("failed to bind window.cef: could not create the object");
        return;
    };
    let mut handler = V8Handler::new(CefApiHandler::default());
    for name in ["brp", "emit", "listen"] {
        let key = CefString::from(name);
        let Some(mut function) = v8_value_create_function(Some(&key), Some(&mut handler)) else {
            cef_error!("failed to bind window.cef: could not create cef.{name}");
            return;
        };
        cef.set_value_bykey(Some(&key), Some(&mut function), V8Propertyattribute::default());
    }
    if global.set_value_bykey(
        Some(&"cef".into()),
        Some(&mut cef),
        V8Propertyattribute::default(),
    ) == 0
    {
        cef_error!("failed to bind window.cef: could not set it on the global object");
    }
}

/// Evaluates each non-empty `CefExtensions` entry in `context`, in name order.
fn eval_extensions(context: &V8Context) {
    /// The `CefExtensions` that the browser process passes in the extensions switch, iterated
    /// in name order.
    ///
    /// Empty when the switch is absent or holds invalid JSON.
    static EXTENSIONS: LazyLock<BTreeMap<String, String>> = LazyLock::new(|| {
        read_switch_json::<BTreeMap<String, String>>(EXTENSIONS_SWITCH).unwrap_or_default()
    });

    for (name, code) in EXTENSIONS.iter().filter(|(_, code)| !code.is_empty()) {
        eval_script(context, code, &extension_script_url(name));
    }
}

/// Returns the script URL that the extension `name` is evaluated under.
///
/// Console errors and DevTools show this URL as the extension's source.
fn extension_script_url(name: &str) -> String {
    format!("cef://localhost/__extensions__/{name}.js")
}

/// Evaluates the browser's `PreloadScripts` in `context` as one script whose URL is the
/// frame's URL.
fn inject_initialize_scripts(browser: &Browser, context: &V8Context, frame: &Frame) {
    let id = browser.identifier();
    let script = INIT_SCRIPTS
        .lock()
        .ok()
        .and_then(|scripts| scripts.get(&id).cloned());
    if let Some(script) = script {
        eval_script(context, &script, &frame.url().into_string());
    }
}

/// Evaluates `code` in `context` under `script_url` and logs an uncaught exception with
/// `cef_error!`.
///
/// CEF also reports the exception to the page console.
fn eval_script(context: &V8Context, code: &str, script_url: &str) {
    let mut retval: Option<V8Value> = None;
    let mut exception: Option<V8Exception> = None;
    let result = context.eval(
        Some(&CefString::from(code)),
        Some(&CefString::from(script_url)),
        0,
        Some(&mut retval),
        Some(&mut exception),
    );
    if result != 0 {
        return;
    }
    match exception {
        Some(ex) => cef_error!(
            "eval failed - url: {}, message: {}, line: {}, column: {}",
            script_url,
            ex.message().into_string(),
            ex.line_number(),
            ex.start_column(),
        ),
        None => cef_error!("eval failed with no exception details - url: {}", script_url),
    }
}
```

`retval` and `exception` must be `Some(...)`, not `None`. CEF's C API refuses to evaluate when either out-pointer is null.

Create `target/cef154-checks/run_for.sh` (run `mkdir -p target/cef154-checks` first). Every runtime check uses it, so logs are colourless and a hung example cannot block the run:

```bash
#!/usr/bin/env bash
# Usage: bash target/cef154-checks/run_for.sh <seconds> <log> <binary> [args...]   (run from the repository root)
# Runs the binary for <seconds> with NO_COLOR=1, then stops it (SIGTERM, then SIGKILL 5 s later).
# Prints "alive" if it was still running at the deadline, or "exited:<code>" if it exited early.
set -u
seconds="$1"; log="$2"; shift 2
NO_COLOR=1 CARGO_MANIFEST_DIR="$PWD" "$@" > "$log" 2>&1 &
pid=$!
waited=0
while [ "$waited" -lt "$seconds" ] && kill -0 "$pid" 2>/dev/null; do sleep 1; waited=$((waited + 1)); done
if kill -0 "$pid" 2>/dev/null; then
  kill "$pid"
  for _ in 1 2 3 4 5; do kill -0 "$pid" 2>/dev/null || break; sleep 1; done
  kill -9 "$pid" 2>/dev/null
  wait "$pid" 2>/dev/null
  echo "alive"
```
