# Bevy 0.20 Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move bevy_cef from Bevy 0.19 / wgpu 29 to Bevy 0.20 / wgpu 30 with CEF unchanged, fix every runtime-only breakage the bump causes, and prepare the 0.14.0 release.

**Architecture:** One branch (`feat/bevy-0.20`) ending in three commits: C1 is a no-op filter refactor on Bevy 0.19, C2 is the whole migration (dependencies, compile fixes, WESL shaders, sprite rebind), C3 is docs and the version bump. Tasks 2–5 are committed individually while working and squashed into C2 in Task 6, so that every commit on the final branch builds and renders.

**Tech Stack:** Rust 1.97.1+ (edition 2024), Bevy 0.20, wgpu 30 / wgpu-hal 30 (Metal), WESL shaders, cef 152.3.0+152.0.6.

**Spec:** `docs/superpowers/specs/2026-10-14-bevy-0.20-migration-design.md`

## Global Constraints

- `cef` and `cef-dll-sys` stay at `152.3.0+152.0.6` in `Cargo.lock`. Never run a bare `cargo update`.
- Bevy `0.20`, bevy_remote `0.20`, wgpu `30`.
- `rust-version = "1.97.1"` in `[workspace.package]`; every member inherits it with `rust-version.workspace = true`.
- Release version `0.14.0`.
- `docs/website/` is not edited.
- Project Rust rules apply (`~/.claude/rules/rust.md`): comments are only `// TODO:` / `// NOTE:` / `// SAFETY:`, no comment cites a spec or plan, every `#[test]` has a two-part doc (`asserted contract` + `Case:`), imports in one block at the top (test modules excepted), no inline fully-qualified paths.
- Static checks must stay clean: `cargo clippy --workspace --all-targets --all-features -- -Dwarnings` and `cargo fmt --all -- --check`.
- macOS-only code is behind `#[cfg(target_os = "macos")]`, CPU-path code behind `#[cfg(not(target_os = "macos"))]`. The non-macOS branches cannot be compiled on the macOS dev machine; CI and the Windows hardware pass in Task 6 are their compile gate.

## Review Focus

1. An app without Bevy's sprite renderer (no `Assets<SpriteMeshMaterial>`) that spawns a `Sprite` webview must not panic. → Task 5 test `missing_sprite_material_assets_do_not_panic`.
2. When Bevy assigns or reassigns a sprite webview's material (first assignment, resize changing `custom_size`, cache hit), that material must be touched so its bind group is rebuilt. → Task 5 test `assigned_sprite_material_is_touched`.
3. A sprite webview carrying Bevy's auto-inserted `Mesh2d`, including one whose `WebviewSource` is inserted late, must never match the mesh input path. → Task 1 tests `sprite_with_mesh2d_is_not_a_mesh_webview` and `meshes_without_sprite_are_mesh_webviews`.
4. On the CPU path, a paint that changes the frame size must be reported as a reallocation, and a same-size paint must not. → Task 5 tests `resized_paint_reports_reallocation` and `same_size_paint_reuses_image` (run on Windows/Linux CI).
5. A user shader that imports `bevy_cef::webview::util::surface_color` must compile at pipeline build. → Task 4 Step 9 and Task 6 run `custom_material` and check the log for shader errors.

```wgsl
fn fragment(
```

```rust
/// Queues `AssetEvent::Modified` for `id` without changing the asset, so Bevy rebuilds the
/// asset's GPU-side data (for a material, its bind group). Does nothing when `id` is not loaded.
///
/// A bare `assets.get_mut(id)` queues nothing: Bevy's `AssetMut` guard only queues the event

pub(crate) fn touch_asset<A: Asset>(assets: &mut Assets<A>, id: impl Into<AssetId<A>>) {
    if let Some(asset) = assets.get_mut(id) {
```

```rust
/// Copies a CPU `OnPaint` frame into an `Image`, reallocating the image when the frame size
/// differs from it. Returns `true` when the image was reallocated, which replaces its GPU
/// texture and makes any material bound to the old texture stale.
#[cfg(not(target_os = "macos"))]
pub(crate) fn update_webview_image(
    texture: &RenderTextureMessage,
    mut image: AssetMut<'_, Image>,
) -> bool {
    let expected_len = (texture.width * texture.height * 4) as usize;
    let dimensions_match = image.texture_descriptor.size.width == texture.width
        && image.texture_descriptor.size.height == texture.height;
    if let Some(data) = image.data.as_mut()
        && dimensions_match
        && data.len() == expected_len
    {
        data.copy_from_slice(&texture.buffer);
        false
    } else {
        *image = Image::new(
            Extent3d {
                width: texture.width,
                height: texture.height,
                depth_or_array_layers: 1,
            },
            TextureDimension::D2,
            texture.buffer.clone(),
            TextureFormat::Bgra8UnormSrgb,
            RenderAssetUsages::all(),
        );
        true
    }
}
```

## v0.14.0

### Breaking Changes

  Bevy module paths such as `bevy_pbr::render::forward_io`) follows Bevy's 0.20 migration guide.

- Sprite webviews no longer receive pointer and wheel input twice when the scene also has a
  `Camera3d` (Bevy 0.20 renders `Sprite` through `Mesh2d`, which the mesh input path matched).

  macOS GPU path and the Windows/Linux CPU path.
- Windows/Linux: webview material preparation is ordered after image preparation, so a resized
  static page no longer keeps a stale texture.

### Known Limitations

- A sprite webview that also uses Bevy's `SpriteMaterial<M>` extension is not rebound after a
  resize.
